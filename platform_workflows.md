# Platform Workflow — Complete Flowcharts

This document describes the end-to-end workflow of the **Manzil AI Online Assessment Platform** through a series of Mermaid flowcharts. It covers authentication, content management, student lifecycle, quiz engine, CUET multi-subject enrollment, performance analytics, and credential management.

---

## 1. Authentication Flow — Dual-Mode Login

The platform supports **two distinct authentication modes**:

- **Admin & Super Admin** — OTP-based phone login (no passwords).
- **Students** — Username + password login. Credentials are auto-generated by the system when a student is created by an org admin.

```mermaid
flowchart TD
    A([User opens app]) --> B{Select login mode}

    B -- Admin / Super Admin --> C[Enter phone number]
    C --> D[POST /auth/send-otp]
    D --> E{Rate limit check\n5 OTPs / 60s?}
    E -- Blocked --> F[429 Too Many Requests]
    E -- OK --> G{User exists with\nthis phone + role?}
    G -- No --> H[403 Forbidden]
    G -- Yes, student --> I{org_id is NULL?}
    I -- Yes --> H
    I -- No --> J[OTP generated → Redis\n5 min TTL]
    G -- Yes, admin --> J
    J --> K[OTP sent via SMTP email\nor printed to console]
    K --> L[User enters OTP]
    L --> M[POST /auth/verify-otp]
    M --> N{OTP in Redis & matches?}
    N -- No/Expired --> O[401 Invalid OTP]
    N -- Yes --> P{Role matches DB?}
    P -- Mismatch --> Q[403 Role mismatch]
    P -- Match --> S[Issue JWT access + refresh token]
    S --> T([User is logged in])

    B -- Student --> S1[Enter username + password]
    S1 --> S2[POST /auth/student-login]
    S2 --> S3{Username found in\nstudent_credentials?}
    S3 -- No --> S4[401 Invalid credentials]
    S3 -- Yes --> S5{bcrypt password match?}
    S5 -- No --> S4
    S5 -- Yes --> S6{Student org_id NULL?}
    S6 -- Yes --> S7[403 Removed from org]
    S6 -- No --> S[Issue JWT access + refresh token]
    S --> T
```

## 4. Student Credential Lifecycle

Student usernames and passwords are system-managed. Org admins create, reset, and reveal credentials.

```mermaid
flowchart TD
    OA([Org Admin adds student]) --> G1[generate_username\nfirst.last + last 4 phone digits\ne.g. john.smith4321]
    G1 --> G2[generate_password\n12-char secure random\ne.g. Kf8mP#rQv2xN]
    G2 --> G3[Store in student_credentials table]
    G3 --> G3a[hashed_password\nbcrypt hash for login auth]
    G3 --> G3b[encrypted_password\nFernet AES for admin reveal]
    G3 --> G4{Student email provided?}
    G4 -- Yes --> G5[Send credentials via SMTP\nBackground task using FastAPI BackgroundTasks]
    G4 -- No --> G6[Print to console logs]

    G5 --> G7([Student receives email\nwith username + password])

    OA2([Org Admin resets password]) --> R1[Generate new random password]
    R1 --> R2[Update hashed + encrypted password in DB]
    R2 --> R3[Email new credentials to student]

    OA3([Org Admin reveals password]) --> V1[POST /org/students/id/reveal-password]
    V1 --> V2[Decrypt encrypted_password via Fernet]
    V2 --> V3[Return plaintext to frontend]
    V3 --> V4[UI shows password for 5 seconds\nthen auto-masks to ••••••••]
```

## 5. Student Journey — Exam Onboarding & Plan Generation

A student picks an exam and generates an AI study plan.

```mermaid
flowchart TD
    ST([Student logs in]) --> SD[Student Home /student/home]
    SD --> SE[Select Exam Centre or Job Centre]

    SE -- Exam Centre --> EX[Browse available exams\nGET /student/pyq-exams\nFiltered by allocated_exams]
    EX --> EP[Select exam + duration\ne.g. GATE, 6 months]
    EP --> TP[Topic proficiency sliders\nStudent rates familiarity per topic]
    TP --> GP[POST /quiz/generate-plan\nexam, duration_months, topic_proficiency]

    GP --> T1{StudyPlanTemplate already\nexists for exam + duration?}
    T1 -- Yes --> T2[Reuse existing template\nSkip AI generation]
    T1 -- No --> T3[Load PYQ content hierarchy\nfrom ContentRegistry]
    T3 --> T4[AI generates week-by-week\nroadmap via Gemini API]
    T4 --> T5[Save StudyPlanTemplate to DB]
    T2 --> T6[Upsert UserStudyPlan\nuser_id, template_id\ncurrent_week=1, completed_weeks empty]
    T5 --> T6
    T6 --> T7[Append exam to\nusers.metadata_.selected_exams\nNo duplicates — multi-exam supported]
    T7 --> T8[Cache plan in Redis 30-day TTL]
    T8 --> PL([Student sees weekly roadmap])
```

## 6. CUET Multi-Subject Enrollment

CUET students enroll in multiple subjects at once. Weekly tests pull questions from all enrolled subjects.

```mermaid
flowchart TD
    ST([Student selects CUET]) --> CS[Choose duration\ne.g. 6 months or 12 months]
    CS --> SB[GET /quiz/available-cuet-subjects\nReturns CUET_CHEMISTRY, CUET_BIOLOGY, etc.]
    SB --> SEL[Student selects subjects\ne.g. Chemistry + Biology + Physics]
    SEL --> EN[POST /quiz/enroll-cuet\nduration_months + subjects list]

    EN --> EN1{Already enrolled\nfor this duration?}
    EN1 -- Yes --> EN2[400 Subjects locked\nafter enrollment]
    EN1 -- No --> EN3[For each subject:]
    EN3 --> EN4[Look up StudyPlanTemplate\nfor CUET_CHEMISTRY etc.]
    EN4 --> EN5[Create UserStudyPlan per subject]
    EN5 --> EN6[Create CuetEnrollment row\nuser_id, template_id, duration_months]
    EN6 --> EN7[Cache each plan in Redis]
    EN7 --> EN8[Update user.metadata_.selected_exams]
    EN8 --> PL([Student sees CUET Hub\nwith all enrolled subjects])

    PL --> VW[GET /quiz/plan-status\nShared weekly roadmap across subjects]
    PL --> WT[POST /quiz/start-cuet-weekly-test\nCombined test from all subjects\nQuestions pooled + split into 3 sub-tests]
```

## 7. Student Weekly Test Flow

The core weekly learning loop — each week has 2 or 3 sub-tests depending on plan duration.

```mermaid
flowchart TD
    PL([Student on study plan]) --> WK[Select a week from roadmap\nGET /quiz/plan-status?plan_id=...]

    WK --> WKL{Week status?}
    WKL -- Completed --> WKD[Week shown as done ✅]
    WKL -- Current or Unlocked --> INS[View test instructions\nGET /quiz/session-meta\nplan_id, week_number, test_number]
    WKL -- Future --> LCK[Week is locked 🔒]

    INS --> ST[POST /quiz/start-weekly-test\nplan_id, week_number, test_number]
    ST --> ST1[Load plan from Redis or DB]
    ST1 --> ST2[Extract week topics & subtopics]
    ST2 --> ST3[Match questions from ContentRegistry\nusing topic & subtopic targeting]
    ST3 --> ST3a[Round-robin interleave\nquestions across subjects]
    ST3a --> ST4[Split into N equal buckets\n2 tests/week for ≥12 months\n3 tests/week otherwise]
    ST4 --> ST5[Create QuizSession in DB\nplan_id, week_number, test_number]
    ST5 --> ST6[Store session state in Redis\nquestions, theta, mode]
    ST6 --> Q([First question served to student])
```

## 8. Quiz Engine — Answer Loop with IRT Adaptive Scoring

Each answer is scored in real-time. Ability estimate (theta) adjusts after every answer.

```mermaid
flowchart TD
    Q([Question displayed]) --> A[Student submits answer\nPOST /quiz/answer\nsession_id, question_id, answer, time_taken]

    A --> A1[Load session state from Redis]
    A1 --> A2[Look up question by composite ID\nsource_file::question_number]
    A2 --> A3{Answer type?}
    A3 -- MCQ --> A4[Exact match scoring\n10.0 correct / 0.0 wrong]
    A3 -- Subjective --> A5[AI evaluation via Gemma LLM\nPartial credit scoring]

    A4 --> A6[Save UserResponse to DB\nquestion_id, answer, score, time_taken]
    A5 --> A6

    A6 --> A7[IRT theta update in quiz_engine\ntheta adapts based on score + difficulty]
    A7 --> A8{More questions?}
    A8 -- Yes --> A9[Return next question\nis_complete = false]
    A9 --> Q
    A8 -- No --> A10[Return is_complete = true]
    A10 --> C([Student calls POST /quiz/complete])
```

## 9. Quiz Completion and Result Saving

When all questions are answered, the session closes and results are fully persisted.

```mermaid
flowchart TD
    C([POST /quiz/complete]) --> C1[Mark QuizSession.completed_at\nUpdate final theta in DB]

    C1 --> C2[Build full response map\nAll scored answers]
    C2 --> C3[AI summary generation via Gemma\nStrengths, weaknesses, suggestions]
    C3 --> C4[Save TestResult to DB\ntotal_score, max_score, theta_final\nai_summary, details JSONB]

    C4 --> C5[Update PerformanceSummary\nPer-topic avg_theta & weak_topics\nScoped by plan_id]
    C5 --> C5a[Invalidate cached AI report\nai_report set to NULL]

    C4 --> C6{Was this a Weekly Test?\nmetadata has plan_id + week_number?}
    C6 -- No --> C8[Return QuizCompleteResponse]
    C6 -- Yes --> C7[Count completed sub-tests\nfor this week]
    C7 --> C7a{All sub-tests done?\ndone_count >= tests_per_week}
    C7a -- No --> C8
    C7a -- Yes --> C9[Add week to completed_weeks\nIncrement current_week in UserStudyPlan]

    C7b{CUET combined test?} --> C7c[Update ALL enrolled\nsubject plans' completed_weeks]
    C9 --> C8
    C7c --> C8

    C8 --> R([Student sees results screen\nscore, AI summary, answer review])
```

## 15. Infrastructure & Deployment

The platform runs as a Docker Compose stack with 5 services:

| Service     | Image                  | Port | Purpose                                         |
|-------------|------------------------|------|-------------------------------------------------|
| `postgres`  | postgres:16-alpine     | 5432 | Primary database (async via `asyncpg`)          |
| `redis`     | redis:7-alpine         | 6379 | Session state, OTP storage, plan caching        |
| `ollama`    | ollama/ollama:latest   | —    | Local LLM inference (Gemma for AI summaries)    |
| `backend`   | Custom (FastAPI + Uvicorn) | 8000 | Python 3.12, Alembic migrations, REST API       |
| `frontend`  | Custom (Vite + Nginx)  | 80   | React + TypeScript SPA, production Nginx build  |

**Database Migrations**: Alembic with async PostgreSQL dialect. Migrations run on container startup.
